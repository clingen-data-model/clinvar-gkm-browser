# AGENTS.md

Guidance for coding agents working in this repository. [README.md](README.md) covers what the project is and how to run it. The design docs in `docs/` are the source of truth for decisions; read the relevant one before changing an area.

## Commands

```sh
pnpm install --frozen-lockfile
pnpm typecheck && pnpm lint && pnpm test   # run all three before calling a change done
pnpm format                                # Prettier (Markdown, SQL and docs/research/ are not formatted)
pnpm e2e                                   # Playwright and axe against the built app over the fixture
pnpm dev                                   # server :8080 and Vite :5173, over data/ (or CLINVAR_DATA_DIR)
scripts/sql.sh [release] [-c "SQL"]        # DuckDB over a derived release, a view per table
```

Tests and e2e use the committed fixture release in `apps/server/test/fixture/`, not the real data. `data/` (downloads, derived releases, scratch) is git-ignored. Most checkouts won't have it, since `scripts/fetch-source.sh` downloads 13 GB and `scripts/derive.sh` takes minutes and up to 8 GB of memory. Ask before running either.

## Layout and boundaries

- `packages/shared/`: Zod API contracts (`src/api/`) and the query language (`src/query/`): filters, dimensions, the three resources and the SQL compiler. It runs in the browser too, so no Node built-ins and no database imports.
- `apps/server/`: Fastify. Each API area is `src/api/<area>/queries.ts` (SQL), and `src/api/routes.ts` wires them up. `src/data/` owns DuckDB and releases.
- `apps/web/`: React 19 SPA. File routes in `src/routes/`, components by area in `src/components/`, URL and API helpers in `src/lib/`. `src/routeTree.gen.ts` is generated by the router plugin; don't edit it.
- `packages/derive/sql/`: the derivation. `schema.sql` is the DDL, `load.sql` the load from upstream parquet, `validate.sql` the post-load checks. `reference-checks.awk` generates one check per `REFERENCES` clause.

ESLint enforces the boundaries: only `queries.ts` files and `src/data/` touch the database; only `routes.ts`, `src/http/` and the composition root import Fastify; browser code imports neither.

## Conventions

**SQL**
- Parameters are always bound through `SqlParams`, never interpolated.
- Give every selected column an explicit `AS` alias, including plain qualified columns (`s.scv_id AS scv_id`).
- Use explicit `ORDER BY` wherever order matters; `UNION ALL` doesn't guarantee one.
- New filters go in the registry in `packages/shared/src/query/filters.ts`. A filter reads columns through `ctx.col(name)`, so it works over `scv` and over either side of a stored pair. A filter needing a column pairs don't carry falls back to a subquery on `scv` automatically (`MissingColumn`).
- Lists and summaries for SCVs, pairs and variants share one compiler (`resources.ts`, `summary.ts`). Extend it rather than writing one-off SQL in a route.

**Data model**
- **Faithful to upstream.** The derivation never invents, drops or repairs rows to satisfy a constraint. A relationship the data breaks is declared `NOT ENFORCED` in a comment and reported in `reference_issue` ([docs/schema.md](docs/schema.md#faithful-to-upstream)).
- **Add a derived table when a common query keeps redoing request-independent work.** Do the work once per release in `load.sql` and have requests filter the result; `scv_classification_pair` is the model ([docs/data.md](docs/data.md#derived-model)). We measured other engines (a DuckDB file, SQLite, ClickHouse); the `clickhouse` branch is kept as a record and isn't merged.
- **A schema change touches several places:** `schema.sql`, `load.sql`, `validate.sql`, `scripts/make-fixture.sh` (then regenerate the fixture), `docs/schema.md`, and the diagrams (`scripts/schema-diagrams.sh`).
- **Vocabularies follow ClinGen's clinvar-ingest-bq-tools,** seeded in `schema.sql`. Conflict levels follow ClinVar Miner's 0–5 scale ([docs/data.md](docs/data.md#conflicts)).

**Web**
- URL state is the page state. Loaders read search params with `searchOf(schema, location)` (`src/lib/route-search.ts`), not `loaderDeps`, and set `shouldReload: true`, so a filter change keeps the page on screen under the busy indicator.
- Search params are parsed as strings (`paramsOf` in `main.tsx`). Don't rely on TanStack's default number decoding.

**Dependencies**
- Versions are exact, at least 7 days old, and dependency build scripts are blocked (`pnpm-workspace.yaml`). Don't loosen these. Approve a build in `allowBuilds` with a comment saying why.
- Don't install anything globally. Use the workspace, or an isolated `uv` environment for Python.

**Code and docs**
- Match the surrounding code's style and comment density. Comments say why, not what.
- Docs are plain prose with a `Status:` line. A decision is recorded as "decided <date>", with the measurements behind it.
- Keep research notes in `docs/research/` and decisions in the main docs.

## Things to ask about first

- Deploying, pushing images (`scripts/build-image.sh --push`) or changing the Cloud Run service or its IAP access ([docs/deploy.md](docs/deploy.md)).
- Any IAM change. Access is granted on the Cloud Run service, not the project.
- Downloading or re-deriving data, or anything else expected to run for more than a few minutes.
- Pushing to GitHub, or force-pushing and rewriting history.
